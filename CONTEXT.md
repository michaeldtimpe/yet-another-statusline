# claude-code-config

Personal Claude Code configuration and a custom statusline that renders session usage, cost, and progress at a glance.

## Rendering (personal fork)

This fork renders a single, compact, **borderless** line of ` · `-separated
segments built by `render_lines()` (no box frame, no wasted space):

```
<min-path> · <branch>/<commit> +U ~M -D ↑ahead ↓behind ✓ · ctx % used/size
  · tkn <billed-weighted> · cch N · <rate>/m · T-H:MM 5h% · 7d % · plan · start +<days-ago> · last <refresh> · <model> <effort>
  (API billing instead: · cost $<session-cost> · api  — replaces the 5h/7d/plan trio)
```

Field meanings: **min-path** = the working directory, home-relative (`~/…`),
always shown **minimized** (each intermediate dir collapsed to its first letter,
the project name kept full) so the data segments keep horizontal room;
middle-ellipsis truncation kicks in only if even the minimized form overflows;
**branch** = a
state-coloured `branch/commit` (green clean+synced, yellow pending = uncommitted
changes or commits to push, red drift/error = behind/diverged/detached)
followed by markers — `+`untracked `~`modified `-`deleted `R`renamed
`↑`ahead `↓`behind, and `✓` when clean, tracking, and synced; **ctx** = current
context-window occupancy (compaction risk) — the `%` comes from the payload's
`context_window.used_percentage` (the same field Claude Code's own right-side
context-low warning uses, so they agree), with raw `total/size` as the fallback
for older payloads; **tkn** = the **Effective Session Tokens** — every token
class for this session weighted by its billing rate (cache write 1.25× or 2×
by TTL, cache read 0.1× — 0.025× on Fable/Mythos —, output `rate_out/rate_in`)
and expressed in input-token-equivalents, so repeated
cache re-reads don't dominate; **cch** = cumulative cache-read
tokens for the session; **<rate>/m** = token throughput per minute; **5h/7d** =
rolling plan quotas with time-to-reset; **plan** = on a subscription (cost is
notional, so not shown). On **metered API/console billing** there are no 5h/7d
windows, so that whole trio is replaced by **cost $<session-cost>** (the session
spend, preferring the payload's `cost.total_cost_usd`) tagged **api**; the dollar
figure is colour-reactive — green under $50, yellow $50–99, red $100+;
**`start +<days-ago> · last <refresh>`** = the count of full 24h periods since
the session began (`+0` same day, `+1` after 24h, `+2` after 48h, …) and the
clock time of the current render (a freshness signal). The
**model** is pinned last; cost ($) and cumulative ↓in/↑out were intentionally
dropped.

It is **responsive**: the path is always minimized up front, and shrinks further
(smart middle-ellipsis) to keep the data segments; only when the path hits its
floor do the lowest-value segments drop (rate → cch → timestamp → plan/quota → tkn);
the branch/`ctx`/model are protected and the model stays pinned last. Terminal
width: Claude Code provides no TTY/`COLUMNS`, so width falls back to an
AppleScript query of iTerm2/Terminal (cached ~5s in `~/.claude/.statusline-width`);
`~/.claude/terminal-width` forces a value.

It is **flat and Monaco-safe**: no Nerd Font glyphs (terse text labels), no
animated/gradient colour, no sparkline, no model "pill". Every visible symbol is
standard Unicode (`∈ · ↓ ↑ • * -`), so a plain non-Nerd font renders it without
tofu (see `test/test_monaco_safe.py`). The old box/pill/gradient/section
machinery was deleted (module is ~1k lines).

## Language

### Token accounting

**Billed Input**:
The session's fresh prompt tokens plus tokens written to the cache (`input_tokens + cache_creation_input_tokens`). Excludes cache hits. Not rendered as its own segment — it feeds **Session Cost**, **Effective Session Tokens**, and the persisted **Day Total**.
_Avoid_: "input tokens" (ambiguous — raw `input_tokens` and the cache-write column are both inputs); also avoid describing it as "shown after `↓`" — that glyph is git's ahead-count marker (`↑N ↓N` in the branch segment), not a token marker, in this flat layout.

**Cache Read**:
Tokens served from the prompt cache (`cache_read_input_tokens`). Rendered as the `cch <count>` segment — the raw, undiscounted count. Billed at 0.1× the input rate, 0.025× on Fable/Mythos models (`TokenAccounting.cache_read_mult`).
_Avoid_: "cache hits" in cost discussions (the per-token price, not the hit-count, is what matters).

**Output**:
Tokens generated by the assistant (`output_tokens`). Not rendered as its own segment; feeds **Session Cost**, **Effective Session Tokens**, and **Day Total**.

**Day Total**:
The persisted sums (`day_in`, `day_cache_read`, `day_out`) of **Billed Input**, **Cache Read**, and **Output** across every session today, kept in `~/.claude/statusline-tokens.log` and rewritten per `session_id` so re-running today's session updates its row instead of double-counting (`TokenLog`). Rows older than 7 days are dropped on the next rewrite (`TokenLog.KEEP_DAYS = 7`). Not itself displayed as a token count anywhere — it's the input to **Day Cost**.

**Effective Session Tokens**:
A single billing-weighted token figure for the *current* session, rendered as the `tkn <count>` segment. Each token class is scaled by its price relative to the input rate — **Cache Read** 0.1× (0.025× on Fable/Mythos), a cache write by its TTL (1.25× for the 5-minute default, 2× for a 1-hour write), **Output** `rate_out/rate_in` (5× on most models) — and the result is expressed in **input-token-equivalents**. This is exactly **Session Cost** divided by the input rate, so it tracks billed dollars while staying in token units. Computed by `TokenAccounting.effective_tokens`.
_Why weighted, not raw_: a raw sum is dominated by **Cache Read**, which is re-counted on every turn (the same cached context, re-read), so a brand-new session would read as 1M+ even though almost nothing fresh was billed. Weighting collapses those re-reads to their true cache-hit cost.
_Avoid_: presenting it as a literal count of tokens the model processed — it is a price-weighted equivalent, not a wire-level token count. Drives no colour. Drops before the protected branch/`ctx`/`model` segments but survives longer than `cch`, `<rate>/m`, the rate-limit quotas, and the timestamp.

**Session Cost**:
The session's billed cost. Taken **authoritatively** from the payload's `cost.total_cost_usd` (what Claude Code actually billed). Only when that field is absent (older Claude Code) does the statusline fall back to a token×list-rate **estimate** (`effective_session_cost`). A present `0.0` is honoured, not treated as absent. Rendered as the `cost $<n>` segment, but only under **API billing marker** — a plan session doesn't show it (see **Plan marker**).

**Day Cost**:
A rate-card **estimate** of today's spend, computed from **Day Total** × list rates (`TokenAccounting.day_cost`) — *not* an authoritative figure. It is necessarily approximate: the day log stores **Billed Input** as one combined number (`input + cache_creation`), so neither cache-write premium (1.25× or 2×, depending on TTL) can be split back out. Not shown in the per-session `statusline_command.py` line at all — it's aggregated across sessions and rendered in `claude/mon.py`'s header row (`day: $<n>`, via `aggregate_day_cost`/`format_header` in `claude/mon/layout.py`).
_Do not_ "fix" the day-cost formula to match session cost — the input it needs isn't stored.

### Context window

**Context Window Size**:
The model's per-session maximum, from the session JSON's `context_window.context_window_size`. Used as the `<size>` half of the `ctx N% used/size` segment's `used/size` pair. Varies by model (e.g. 200K, 1M).

**Compaction-Risk Zone**:
Token consumption above the 150K soft limit (`SOFT_LIMIT`). Auto-compaction looms and output quality degrades regardless of how much **Context Window Size** remains. Drives the `ctx` segment's colour, computed as `fill_colour(total / 150K * 100)` — a three-stop ladder: green below 70% of 150K, yellow at 70%+, red at 90%+. This is the *colour* source only; the `%` number shown in `ctx N%` is a separate, unrelated figure — the payload's own `context_window.used_percentage` (against **Context Window Size**, not the 150K limit) — so the two are deliberately decoupled (see **Relationships**).
_Avoid_: "context full" — a session can show a low `ctx N%` (plenty of room left in a 1M-context model) while still rendering red, because the colour tracks raw tokens against the 150K zone, not the displayed percentage.

### Thinking effort

**Effort Level**:
The discrete settings of extended thinking effort (e.g. `low`, `medium`, `high`, `xhigh`, `max`), read from `effort.level`. Shown only when `thinking.enabled` is true, appended in italics after the model name — `session.model_thinking` returns `f'{level}/fast'` when `fast_mode` is also set, otherwise just `level` (see the `Opus 4.7 1M xhigh` example in `README.md`). It no longer drives any background fill or colour — that was part of the deleted pill/gradient renderer.
_Avoid_: "thinking level" (overloaded — the *level* names a setting, the *effort* names the resource it spends).

**Anchor** — _legacy (theme data only, not rendered)_:
`ModelColors.anchor` is still a field on every theme's per-model colour table in `claude/statusline/themes.py`, but nothing reads it: `Renderer.model_colour` only uses `ModelColors.label`. It was the left-edge identity colour of the old model-row pill gradient. Left in the dataclass for now; don't build new behaviour on it without first re-checking whether it's still unread.

**Shift** — _legacy (theme data only, not rendered)_:
`ModelColors.warm_shift` / `cool_shift` are likewise still theme fields, still accepted as a `--bg-shift {warm,cool}` CLI flag and stored on `Renderer.bg_shift`, but that stored value is never read again — there's no gradient left to shift. The flag is currently a no-op.
_Avoid_: "hue shift" — and don't assume passing `--bg-shift` changes anything in the current renderer.

### Theming

**Theme**:
The complete set of colour decisions the statusline draws with. `Renderer._apply_theme` copies every `Theme` slot onto `self`, but `render_lines` only actually reads a handful: `label`, `pwd`, `ctx`, `tok`/`tok_dim`, `tok_icon`, `dirty`, `commit`, `model`, `white_brt`, and the three-stop traffic-light ladder (`safe`/`warn`/`alert`, via `fill_colour`) plus each model's `ModelColors.label` (via `model_colour`). The rest of the ~25 slots on `Theme` and `Renderer` (`border`, `branch`, `session`, `skills`, `time`, `tok_day`/`tok_day_dim`, `cost`, `bar_fill`/`bar_empty`, `dim_green`, `icon_path`, `arrow`, `yellow`, the class-level `OPUS`/`SONNET`/`HAIKU` shortcuts, and **Anchor**/**Shift**/**Pill Foreground** below) are assigned but never read by the current renderer — carried over from the boxed/pill ancestor. Lives as a `Theme` dataclass instance in `claude/statusline/themes.py`. Selected at runtime via `--theme=name`, `CLAUDE_STATUSLINE_THEME`, or `~/.claude/statusline-theme` — in that priority order, falling back to `claude-dark`.
_Avoid_: "palette" as a synonym (a palette is a *source* — Catppuccin Latte, Solarized Light — and a **Theme** is the fully populated dataclass derived from one); avoid describing the theme as driving a border or gradient — this fork is borderless and flat.

**Pill Foreground** — _legacy (theme data only, not rendered)_:
`Theme.pill_fg_dark` / `pill_fg_light` are still copied onto `Renderer.pill_fg_dark` / `pill_fg_light` in `_apply_theme`, but no segment in `render_lines` reads them — there's no model pill left to paint text on top of.

### Rate limits

**Five-Hour Limit**:
The rolling 5-hour quota Anthropic publishes in `rate_limits.five_hour`. Rendered countdown-first as `T-<time-to-reset> <pct>%` — the time-to-refresh is the signal, so it leads and the `5h` label is dropped. Only when no `resets_at` is available (no countdown to imply the bucket) does it fall back to the labelled `5h <pct>%` form.

**Seven-Day Limit**:
The weekly quota in `rate_limits.seven_day`. Shown in the model row after the Five-Hour Limit as `7d <pct>%`.

**Plan marker**:
A `plan` tag rendered next to the rate-limit quotas whenever any quota is present (subscription plans expose `rate_limits`; metered API/console use does not). It signals that **Session Cost** is the *notional* API-equivalent figure Claude Code reports, not incremental spend.

**API billing marker**:
When no quota is present (metered API/console use exposes no `rate_limits`), the 5h/7d/`plan` trio is meaningless and is replaced by **cost $<session-cost>** + an `api` tag. The cost prefers the payload's authoritative `cost.total_cost_usd` and falls back to the token×rate estimate (`effective_session_cost`). Here the dollar figure is *real billed spend*, the inverse of the `plan` case where cost is notional, so it is **colour-reactive** as a spend warning: green under $50, yellow $50–99, red $100 and above.

## Relationships

- **Billed Input** and **Output** aren't shown as their own segments any more; only **Cache Read** (`cch`) is displayed raw. All three still feed **Session Cost**, **Effective Session Tokens**, and **Day Total** internally.
- The `ctx` segment's `<used>/<size>` half tracks **Context Window Size**; its *colour* instead tracks raw consumption against the **Compaction-Risk Zone**'s 150K threshold. These are deliberately decoupled — a session can show a low `used/size` fraction (huge **Context Window Size**) while still rendering red.
- **Anchor**, **Shift**, and **Pill Foreground** are theme-dataclass fields with no current reader — they predate the flat single-line rewrite and describe the deleted pill/gradient model row.
- A plugins/skills row and a subagent/task row existed in the boxed ancestor; neither is rendered in this fork's `render_lines`, and no data class for either still exists in `statusline_command.py` (unlike the theme-only legacy fields above, there's nothing left to point to).

## Example dialogue

> **Dev**: "Why is `ctx` red but only reads `12%`?"
> **User**: "Because we're on a 1M-context model — `12%` is tokens against **Context Window Size**, plenty of headroom. The colour is a different number: raw tokens against the 150K **Compaction-Risk Zone**, and we're past it. Quality degrades there whether the window has room or not."

> **Dev**: "What's the difference between `tkn 16.4M` and `cch 157.6M`?"
> **User**: "`cch` is the raw **Cache Read** count — the same cached context re-read every turn, so it balloons fast. `tkn` is **Effective Session Tokens** — the whole session weighted by what it actually cost, so a cache read only counts for a tenth (or a fortieth, on Fable/Mythos) of what it would as fresh input. `tkn` tracks the bill; `cch` tracks raw re-reads."

## Flagged ambiguities

- "input tokens" was ambiguous between raw `input_tokens` and **Billed Input** (which includes cache writes). Resolved: **Billed Input** is the canonical term for that sum, even though — since the flat rewrite — neither is displayed as its own segment.
- "context limit" was ambiguous between **Context Window Size** (per-model capacity, shown in `ctx`'s `used/size`) and the 150K **Compaction-Risk Zone** threshold (drives `ctx`'s colour only). Resolved: these are distinct and deliberately decoupled — see **Relationships**.
